## Why

`assets/readability-bundle.js` is a build artifact — it's generated by `scripts/download_readability.sh`, which downloads Mozilla's Readability.js + Readability-readerable.js from unpkg and concatenates them. Despite being derivable on demand, the ~82KB bundle is committed to git, bloating the repo history with a third-party vendor file and creating a staleness risk (nothing forces it to be regenerated when `download_readability.sh` changes). Platform build steps are also currently undocumented tribal knowledge (shell one-liners passed around outside the repo), with no guarantee the bundle exists before `flutter build` runs.

## What Changes

- **Untrack** `assets/readability-bundle.js` from git and add it to `.gitignore` — the file remains required locally (referenced by `pubspec.yaml`) but is no longer version-controlled.
- **New script** `scripts/build_ios.sh` — regenerates the readability bundle, then runs the existing iOS release sequence (`flutter clean && rm ios/Podfile.lock pubspec.lock && rm -rf ios/Pods/ ios/Runner.xcworkspace && flutter build ipa --no-sound-null-safety`).
- **New script** `scripts/build_android.sh` — regenerates the readability bundle, then runs `flutter build apk --split-per-abi --no-sound-null-safety`.
- **Modify** `scripts/download_readability.sh` to skip re-downloading when `assets/readability-bundle.js` already exists (idempotent), so repeated local builds don't hit the network every time; both new build scripts can still force a refresh with a `--force` flag.

## Capabilities

### New Capabilities
- `release-build-scripts`: Defines the iOS/Android release build entry points, including the requirement that the readability bundle asset is generated (not committed) before each platform build runs.

### Modified Capabilities

## Impact

- `assets/readability-bundle.js` — removed from git tracking via `git rm --cached`; added to `.gitignore`
- `scripts/download_readability.sh` — gains idempotent skip-if-exists behavior and a `--force` override
- `scripts/build_ios.sh`, `scripts/build_android.sh` — new files, no existing code affected
- `pubspec.yaml` — unaffected; the asset path reference is unchanged, only its git-tracking status changes
- No app runtime behavior changes; this is build tooling only
